==================================================
VISUAL MODEL
==================================================

Individual parking markers are compact, fully rounded status-color pills with
bold availability text. Known states use white text and a white outline.
Selection enlarges the pill, adds a colored aura and strong status glow, and
reveals a downward pointer. Unknown uses a near-white/slate treatment.

Clusters are white pills with a dark area-count label, status-color dot, and
pale-blue outline. Selected clusters use a blue border and blue shadow. They do
not use an aura or pointer.

At wider zoom levels, separate cell-summary pills replace availability bubbles.
Search destination and user location are separate red-pin and blue-dot families.

==================================================
AVAILABILITY LOGIC
==================================================

Processing order:
1. Math.round(value)
2. Clamp to 0 through 100 inclusive
3. High if >=66; medium if >=33; otherwise low

65.5 -> 66 -> high
32.5 -> 33 -> medium
Above 100 -> 100
Below 0 -> 0

The bubble treats null and non-finite input as unknown. The lower-level utility
alone normalizes NaN to 0, but the component's finite-value gate runs first.

Known text example: 72%
Unknown text: em dash (—)
Unknown accessibility: Parking availability unavailable

==================================================
MOVING / PERFORMANCE MODE
==================================================

Starts during camera movement and clears 150 ms after the final event.

Visual changes:
- reduced, tighter shadows
- marker card entry animation omitted
- selected aura and pointer hidden
- selected scale, border, and elevation remain
- high/medium/low fill colors remain unchanged
- unknown spot remains near-white

These are performance optimizations, not a new semantic status.

==================================================
POSITIONING AND LAYERS
==================================================

Projection:
translateX = projected x - canvas width / 2
translateY = projected y - canvas height / 2

The canvas is centered on the coordinate and is larger than the visual pill so
effects and pointer can fit. Selected local marker z-index is 2; default is 1.

Map layer: z 0, elevation 0
Marker layer: z 10, elevation 2
Marker highlight layer: z 20, elevation 4
Floating controls: z 40, elevation 6

Search destination and user location share the highlight layer. User location
is rendered later and may paint above destination at an exact overlap.

==================================================
DESIGNER-EDITABLE VS LOGIC-DEPENDENT
==================================================

SAFE VISUAL VARIABLES, SUBJECT TO IMPLEMENTATION REVIEW:
Colors, borders, dimensions, radius, padding, type, shadows, aura, pointer,
animation duration, and spring feel.

LOGIC-DEPENDENT / BEHAVIORAL:
Availability thresholds, semantic zoom boundaries, cluster radii, marker caps,
cell aggregation, count content, collision priority, projection, data, selected
substitution, and search recommendations.

==================================================
DESIGN REVIEW OPPORTUNITIES
==================================================

- Multiple competing availability palettes and threshold systems
- White text contrast on bright green/orange
- Pointer appears only in selected state
- Selected state combines scale, border, aura, shadow, and pointer
- Normal production clusters nearly always use only small tier
- Unknown-state inconsistency across bubble, cluster, and detail UI
- Destination entry/user pulse lack explicit reduced-motion handling
- Mixture of hardcoded colors and centralized NativeWind tokens

==================================================
TECHNICAL OBSERVATIONS — NO CODE CHANGED
==================================================

- Cluster accessibility can produce duplicated wording such as
  "12 areas parking areas."
- Derived square canvasSize values are not authoritative in projection.
- Outgoing features are retained for 200 ms, while keyed wrappers provide the
  visible stage transition.
- A third marker overlay layer exists structurally but is empty in the inspected
  production path.
- The legacy src/app/parking/[id].tsx route uses provider-native markers and is
  not part of this custom bubble system.

For exact source-per-token traceability, full state tables, and Figma formulas,
see docs/parking-bubble-design-spec.md.
